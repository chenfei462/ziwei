# 生产部署与运维手册

本文档用于紫微星垣网页端的预发、生产部署、数据库迁移、回滚、备份、监控和人工验收。

## 环境分层

- 开发：`NODE_ENV=development`，可使用默认 `data/phase-store`，支付使用 sandbox 或 `mock_checkout`。
- 预发：使用独立域名、独立 `ZIWEI_STORE_DIR` 或独立 PostgreSQL schema，开启完整日志、指标、链路追踪、告警和 webhook 签名校验。
- 生产：必须配置 `NEXT_PUBLIC_SITE_URL`、管理员 token、后台第二因子、Redis REST 限流、报告导出对象存储、日志/指标/告警/追踪、支付密钥、webhook secret、备份任务和只读/读写分离账号。

## 必需环境变量

- `NEXT_PUBLIC_SITE_URL`：生产域名，例如 `https://example.com`。
- `ZIWEI_STORE_DIR`：文件型持久化目录。迁移 PostgreSQL 后保留为应急导出目录。
- `ZIWEI_E2E_STORE_TEST_DOUBLE`：仅自动化端到端测试允许设置为 `true`。该开关会让生产构建产物在无 `DATABASE_URL` 时使用文件 store 测试替身，`database.ready` 仍不得作为正式上线通过依据；生产、预发和真实用户流量环境必须关闭。
- `DATABASE_URL`：PostgreSQL 连接串，生产必须配置。未配置时 `/api/launch/config` 会返回 `database.ready=false`，product repository mode 会失败关闭，不得正式上线。
- `DIRECT_DATABASE_URL`：迁移和应急维护使用的直连 PostgreSQL 连接串，生产建议配置并由密钥管理系统注入。
- `STRIPE_SECRET_KEY`、`STRIPE_WEBHOOK_SECRET`、`STRIPE_CHECKOUT_BASE_URL`：真实支付 provider 配置。
- `PHASE10_PRODUCTION_PAYMENT_ENABLED`、`PHASE10_PAYMENT_ROLLOUT_PERCENT`、`PHASE10_PAYMENT_ROLLBACK`：支付灰度和回滚开关。
- `MOCK_PAYMENT_WEBHOOK_SECRET`：预发和自动化测试使用。
- `PHASE10_ADMIN_TOKEN`：后台管理员 token，应由密钥管理系统注入。
- `PHASE10_OPS_MFA_ENABLED`：生产必须设置为 `true`，开启 `/internal/*` 和所有 ops API 的第二因子校验。
- `PHASE10_OPS_MFA_CODE`：后台第二因子密钥，应由密钥管理系统注入，并通过反向代理、BFF 或内部网关转换为 `x-admin-mfa-code` header；不得写入前端 bundle、日志、公开接口响应或客服工单。开启 MFA 但未配置该值时，后台会失败关闭。
- `SMS_PROVIDER`、`SMS_ACCESS_KEY`、`SMS_TEMPLATE_ID`：手机号验证码登录服务配置。`mock_sms` 只允许测试/预发使用；生产应设置 `SMS_PROVIDER=http_sms`，并由受保护短信网关转接阿里云短信、腾讯云短信或等效服务商。
- `SMS_HTTP_ENDPOINT`、`SMS_HTTP_SIGNING_SECRET`：`http_sms` 生产短信网关配置。应用会把手机号、验证码、模板、用途、nonce 和签发时间发送到该 HTTPS endpoint，并使用 `x-ziwei-sms-signature: sha256=<hmac>` 签名。网关返回非 2xx 时 `/api/account/sms/send` 返回 `SMS_DELIVERY_FAILED`，不保存可用验证码挑战。
- `SMS_TEST_FIXED_CODE`：`SMS_PROVIDER=mock_sms` 时的固定验证码，仅供自动化测试。生产不得把固定验证码 provider 暴露给真实用户。
- `SESSION_SECRET`：正式登录会话签名密钥，至少 24 字符。生产必须由密钥管理系统注入；配置后 `zv_visitor_id` 和 `zv_member_id` cookie 使用 HMAC-SHA256 签名，服务端拒绝签名不匹配的会话。
- `TRUSTED_IDENTITY_HEADER_SECRET`：受保护网关或 BFF 注入 `x-trusted-visitor-id`、`x-trusted-member-id` 时使用的 HMAC 签名密钥。生产公开请求默认只信 HttpOnly cookie；如需由网关注入身份，必须同时注入 `x-trusted-identity-timestamp` 和 `x-trusted-identity-signature: sha256=<hmac>`。未签名的 `x-member-id`、`x-visitor-id` 和 query 身份参数仅用于开发/自动化测试，不作为生产安全边界。
- `ZIWEI_RATE_LIMIT_REDIS_REQUIRED`：生产必须设置为 `true`，要求所有用户写接口使用 Redis REST 限流；未配置 Redis 时写接口会失败关闭并返回 `RATE_LIMIT_REDIS_NOT_CONFIGURED`。
- `ZIWEI_RATE_LIMIT_REDIS_REST_URL`：Redis/Upstash REST 地址，例如 `https://xxx.upstash.io`；不得在前端暴露。
- `ZIWEI_RATE_LIMIT_REDIS_REST_TOKEN`：Redis/Upstash REST token，应由密钥管理系统注入；不得写入前端 bundle、日志、公开接口响应或客服工单。服务端只把 SHA-256 后的 client/path key 写入 Redis。
- `ZIWEI_EXPORT_STORAGE_REQUIRED`：生产必须设置为 `true`，要求报告导出预览使用 S3/OSS/COS 兼容对象存储；未配置对象存储时导出预览会失败关闭并返回 `EXPORT_STORAGE_NOT_CONFIGURED`。
- `ZIWEI_EXPORT_STORAGE_ENDPOINT`、`ZIWEI_EXPORT_STORAGE_BUCKET`：对象存储 endpoint 和私有桶名称，桶策略默认私有。
- `ZIWEI_EXPORT_STORAGE_ACCESS_KEY_ID`、`ZIWEI_EXPORT_STORAGE_SECRET_ACCESS_KEY`：对象存储写入凭据，应由密钥管理系统注入；不得写入前端 bundle、日志、公开接口响应或客服工单。
- `ZIWEI_EXPORT_STORAGE_PUBLIC_BASE_URL`：导出资产签名访问或 CDN 基地址；导出 URL 和对象 key 使用哈希路径，不包含报告 ID、完整出生日期、出生时间、地点或用户身份。
- `OBS_LOG_SINK`：结构化日志 sink，例如托管日志平台或自建采集入口。
- `OBS_METRICS_ENDPOINT`：指标上报入口，用于 5xx、429、403、支付、权益、报告生成和分享漏斗监控。
- `OBS_ALERT_WEBHOOK_URL`：告警 webhook，例如企业微信、飞书、PagerDuty 或自建告警路由。
- `OBS_ALERT_WEBHOOK_SECRET`：告警 webhook HMAC-SHA256 签名密钥；`POST /api/ops/reconciliation/alerts` 会用它生成 HMAC-SHA256 签名并投递脱敏告警 envelope；未配置时只允许 dry-run/blocked，不得宣称外部告警已送达。
- `OBS_TRACE_EXPORTER`：链路追踪 exporter，例如 OTLP HTTP endpoint。
- `OBS_BACKUP_HEALTHCHECK_URL`：备份任务成功后回调的健康检查 URL；超过阈值会触发备份 stale 告警。
- `WECHAT_JS_SDK_APP_ID`：微信公众号或开放平台 appid，用于 H5 微信分享。
- `WECHAT_JS_SDK_TICKET`：服务端定时刷新后的 `jsapi_ticket`。不得写入前端 bundle、日志、公开接口响应或客服工单。
- `WECHAT_JS_SDK_ENABLED`：设置为 `true` 后才允许 `/api/wechat/jssdk` 返回签名配置。
- `ZIWEI_DISABLED_CHANNELS`：逗号分隔的暂停渠道列表，例如 `short_video,qr_event`。应用会在服务端拒绝对应渠道的 `/api/channel/entry`、渠道分享创建和 `/api/growth/channel-event` 写入，返回 `CHANNEL_DISABLED`；`/api/ops/growth/channel-dashboard` 仍返回 `disabled_channels` 和聚合 `channel_health`，用于授权复盘，不包含出生资料、联系方式、原始分享正文或用户身份明文。

2026-06-07 生产工程增量：开发/测试文件型 store 的路径拼接已通过 runtime helper 隔离，避免 Turbopack 在 `next build` 阶段把 `data/phase-store` 历史 JSON 作为静态文件模式广泛追踪。该优化只降低构建噪声和过度追踪风险，不改变“生产必须使用 PostgreSQL”的上线门禁。

当前 `data/phase-store` 只能作为开发、自动化测试和应急导出目录，不能作为正式生产主库。生产数据库交付物已经固定在：

- 初始迁移：`prisma/migrations/20260525000100_china_market_delivery/migration.sql`
- 服务端 Prisma Client 单例：`src/repositories/prismaClient.ts`。生产配置 PostgreSQL `DATABASE_URL` 且已执行 `npx prisma generate` 后，product repository 会自动接入生成的 Prisma Client；未配置数据库时生产失败关闭。
- 上线门禁：`/api/launch/config` 中的 `database.ready` 必须为 `true`

当前 store bucket 可一一映射为 PostgreSQL 表：

- `users`、`anonymous_visitors`、`identities`
- `birth_profiles`、`charts`、`chart_owners`、`interpretations`
- `reports`、`report_versions`、`shares`
- `orders`、`payment_events`、`entitlements`、`refunds`
- `support_tickets`、`analytics_events`、`audit_logs`
- `ai_generation_logs`、`content_review_records`、`rule_versions`
- `admin_accounts`、`ops_actions`、`channel_attributions`、`wechat_sessions`、`data_deletion_requests`

迁移步骤：

1. 在预发设置 `DATABASE_URL` 和 `DIRECT_DATABASE_URL`。
2. 执行 `npx prisma generate` 和 `npx prisma migrate deploy`，确认客户端、上述表、索引和唯一约束全部存在。
3. 先执行 dry-run：`npx tsx scripts/migrate-phase-store-to-postgres.ts --dry-run --source data/phase-store`，核对命盘归属、短信验证码挑战、运营漏斗、订单、checkout、支付事件、权益、AI 生成记录和内容审核记录数量。
4. 配置真实 `DATABASE_URL` 后执行导入：`npx tsx scripts/migrate-phase-store-to-postgres.ts --source data/phase-store`；出生资料、手机号、微信身份和工单内容必须按加密或哈希字段导入。
5. 双写一段时间：命盘归属、短信验证码挑战、短信登录用户/匿名访客绑定、运营漏斗事件、订单、checkout、支付事件、权益、AI 生成记录和内容审核记录已具备 Prisma adapter；报告草稿/版本、分享快照、客服工单、删除申请等 bucket 继续按表映射导入 PostgreSQL，并在切换前保持文件 store 和 PostgreSQL repository 同时写入，读路径优先 PostgreSQL。
6. 对账记录数量、关键 ID、支付事件幂等键、权益发放结果、AI 生成 digest 和审核状态。
7. 切换为 PostgreSQL 单读写，保留文件导出作为回滚备份。

## 部署流程

1. 安装依赖：`npm ci`。
2. 生成 fixture：`npm run generate:fixtures`。
3. 生成 Prisma Client：`npx prisma generate`。
4. 必跑门禁：`npm run typecheck`、`npm test`、`npm run build`、`npm run test:e2e`。
5. 在预发验证建盘、报告、分享、订单、支付 webhook、退款、权益补发、客服工单、后台权限。
6. 生产部署使用 Next.js 标准构建输出；容器或平台部署时挂载持久化目录或连接 PostgreSQL。
7. 支付生产开关按 1%、10%、50%、100% 灰度放量；出现异常时设置 `PHASE10_PAYMENT_ROLLBACK=true`。

## 回滚

- 应用回滚：回退到上一构建产物，保持数据库向后兼容。
- 支付回滚：立即设置 `PHASE10_PAYMENT_ROLLBACK=true`，checkout 回到 sandbox 或停止生产跳转。
- 数据回滚：优先补偿写入，不做破坏性删除；必要时从最近备份恢复到新库并切换连接。
- 内容回滚：通过后台内容规则禁用异常规则，已生成报告保留版本号并重新生成新版本。

## 备份与恢复

- 文件 store：每天快照 `data/phase-store`，保留 30 天；支付和权益 bucket 每小时增量备份。
- PostgreSQL：开启 PITR，至少每日全量、15 分钟 WAL 归档。
- 恢复演练：每月至少一次在预发恢复备份，验证用户、命盘、订单、支付事件、权益、客服和分享记录数量。

## 日志、监控和告警

- 结构化日志必须包含 `request_id`、`member_id` 或 `visitor_id`、`route`、`status`、`error_code`；`member_id`、`visitor_id` 进入日志前必须哈希，消息字段必须脱敏完整出生日期、出生时间、精确地点、明文邮箱、明文手机号、图片 payload、token、authorization 和 webhook secret。
- 关键指标：建盘成功率、报告生成失败率、分享打开率、订单支付转化率、支付失败率、重复 webhook 数、退款率、权益发放延迟、403 越权次数、429 限流次数、后台操作数。
- 告警阈值：5 分钟 5xx 超过 2%、支付 webhook 签名失败突增、权益发放失败、订单 fulfilled 后无 entitlement、后台未授权访问突增、备份失败。
- 代码侧 `evaluateOperationalAlerts` 已内置 5xx、支付签名失败、权益缺口、后台未授权访问和备份 stale 规则；支付对账异常可由 `ops_admin` 调用 `POST /api/ops/reconciliation/alerts` 生成脱敏 webhook envelope、幂等 key、endpoint digest 和 HMAC-SHA256 签名摘要，并写入 `ops_payment_alert_webhook_prepared` 审计。接入告警平台前需在预发用假事件验证 webhook、去重、升级和值班通知。
- 报告生成任务只记录 request digest、摘要、尝试次数、错误码和客服兜底工单；正式异步 worker 接入后应对 `retry_pending` 任务做指数退避，达到最大次数时保持客服兜底并触发人工退款/补偿检查。
- 报告导出任务只允许写入私有对象桶；对象 key 必须为 `reports/<format>/<sha256>.<format>`，不得包含 report_id、member_id、visitor_id、出生日期、出生时间或地点原文。

## 安全检查

- 所有用户写接口必须执行 Origin 校验和 rate limit；生产需确认 `/api/launch/config.rate_limit.provider=redis_rest`、`ready=true`、`production_required=true`，并通过重复写请求验证 429 计数在多实例间共享。
- 正式登录链路必须确认 `/api/launch/config.login.session.secretConfigured=true`；使用篡改后的 `zv_member_id` 或 `zv_visitor_id` cookie 访问私有命盘、报告、订单和权益应被当作未登录或无权访问。
- 生产建盘必须确认 `/api/launch/config.birth_data_encryption.ready=true`；`ZIWEI_BIRTH_DATA_ENCRYPTION_KEY` 不得进入前端、日志、错误上报或运营导出，缺失时不得开放 PostgreSQL 建盘写入。
- 短信登录生产链路必须确认 `/api/launch/config.login.providers.sms.provider=http_sms`、`ready=true`，并在预发用真实短信网关演练签名校验、模板变量、失败关闭、频控和服务商告警。
- 报告导出预览生产需确认 `/api/launch/config.export_storage.provider=s3_compatible`、`ready=true`、`production_required=true`；缺失任一对象存储环境变量时不得开放导出入口。
- 生产需确认 `/api/launch/config.observability.ready=true`；缺失日志 sink、指标 endpoint、告警 webhook、追踪 exporter 或备份健康检查时不得正式上线。
- 支付 webhook 只依赖 provider 签名和幂等键，不依赖浏览器 Origin。公开回调入口为 `/api/payment/webhook?provider=stripe_checkout|wechat_pay_reserved|alipay_reserved|mock_checkout`；微信支付必须提供 `wechatpay-signature`，支付宝必须提供 `alipay-signature`，Stripe 必须提供 `stripe-signature`，mock 必须提供 `mock-signature`。
- 生产身份边界必须使用签名 HttpOnly cookie 或由受保护网关 HMAC 签名的 trusted identity headers；不要把客户端可控的 `x-member-id`、`x-visitor-id` 或 query 参数作为生产鉴权依据。
- 日常星垣、星曜图鉴、成就和挑战进度接口必须使用服务端解析出的当前主体；预发需验证 `/api/daily/check-in`、`/api/daily/streak`、`/api/star-atlas*`、`/api/member/achievements`、`/api/challenge/list`、`/api/challenge/join`、`/api/challenge/check-in` 在 query/body 伪造其他 `member_id` 时仍写入或返回当前 cookie/受信 header 主体的数据。
- 渠道入口、渠道分享和增长事件必须使用服务端解析出的当前主体；预发需验证 `/api/channel/entry`、`/api/share/create`、`/api/growth/channel-event`、`/api/growth/referral-event` 在 body 伪造其他 `visitor_id`/`member_id` 时仍按当前 cookie/受信 header 写入，并在缺少访客 cookie 时下发新的 `zv_visitor_id`。`/api/channel/entry.landing_url` 必须指向 `/chart/new`，渠道分享 URL 不得包含 `visitor_id` 或 `/phase14`。

- `/api/privacy/delete-request` 只能为服务端解析出的当前 `zv_visitor_id`/`zv_member_id` 或受信 header 身份创建删除/注销申请；缺少既有会话返回 `DELETION_IDENTITY_REQUIRED`，请求体中声明其他 `member_id`/`visitor_id` 返回 `DELETION_SUBJECT_FORBIDDEN`。
- `/api/ops/deletion-requests` 只允许运营或客服访问，完成、拒绝、取消删除/注销申请必须由 `ops_admin` 携带二次确认参数执行；响应和审计 note 必须脱敏出生资料、联系方式和身份资料。
- `/api/ops/users`、`/api/ops/reports`、`/api/ops/shares` 只返回运营摘要，不返回联系方式哈希、报告正文、完整 trace、完整出生资料或私密付费内容；需要查看 chart/report/order/share/support_ticket 敏感详情时，只能由 `ops_admin` 调用 `/api/ops/sensitive-record`，请求体必须包含 `record_type`、`record_id`、`reason` 和 `second_confirmed=true`，并由服务端写入 `audit_logs`。`support_agent` 和 `content_reviewer` 调用该接口必须返回 403。
- `/api/ops/audit-logs` 只允许 `ops_admin` 查询，返回脱敏后的管理员审计日志；`/internal/ops` 可加载审计日志，并在二次确认后通过 `/api/ops/sensitive-record` 查看单条敏感详情，默认列表仍只展示脱敏 metadata。
- `/api/ops/rule-profiles`、`/api/ops/rule-profiles/[id]`、`/api/ops/chart/compare-rules`、`/api/ops/knowledge/search` 和 `/api/ops/knowledge/node/[id]` 允许 `ops_admin`、`support_agent`、`content_reviewer` 查询规则版本、规则对比和知识图谱；响应不返回出生资料、报告正文或模型 prompt。`/api/ops/rule-profiles/default` 只允许 `ops_admin`，必须包含 `profile_id`、`reason`、`second_confirmed=true`，并拒绝 `experimental` 或 `needs_consultant_review` 规则；成功后写入 `rule_versions.active_default` 与 `ops_rule_profile_promoted` 审计。
- `/api/ops/synastry/create` 和 `/api/ops/timeline/interpret` 只允许后台角色使用合盘对照和年度/月度主题扩展；旧公开 `/api/synastry/create`、`/api/timeline/interpret` 必须保持 404。该扩展仍是内部工具，不得作为大众公开购买或分享主流程的安全边界。
