# 投资人认可导向优化路线图（Internal）

本文是内部冲刺备忘录，用来暴露缺口、安排优先级和记录复盘，不作为投资人或评委的第一外发材料。外发入口请使用 `docs/trae-submission/final-submission-control-room.md`、`investor-one-pager.md`、`investor-mini-deck.md`、`investor-deck.html` 和 `community-post.md`。

## 目标

让紫微星垣在 Trae CN 黑客松中不仅“能跑”，还要让企业家和早期投资人快速看到四件事：

- 有明确用户场景：传统文化、自我观察、移动端分享和轻量陪伴。
- 有产品闭环：免费观察卡、AI 转译、脱敏分享、7 日挑战、私密报告和商业化入口。
- 有工程可信度：隐私边界、权限校验、支付沙箱、生产数据库 readiness、测试和部署文档。
- 有下一阶段投资价值：可以用小成本验证获客、留存、转化和内容安全。

## 当前强项

1. 已经越过普通原型阶段。`README.md` 描述了公开路径、账号、报告、分享、支付、运营、合规和测试体系，说明项目不是单页 Demo。
2. 核心体验已收敛到“星垣观察卡”。`src/app/page.tsx`、`src/app/chart/new/page.tsx`、`src/app/chart/[id]/page.tsx`、`src/app/share/[id]/page.tsx` 都在使用观察卡、AI 转译、脱敏分享和 7 日挑战语义。
3. 隐私和合规意识强。`src/app/share/[id]/page.tsx` 明确隐藏生日、时间和地点；`src/app/report/[id]/page.tsx` 对完整报告、访问层、规则追溯和免责声明做了区分。
4. 工程可信度较高。`package.json` 已有 `verify:public`，串联 typecheck、公开主流程单测、build 和 public e2e；`prisma/schema.prisma` 和 `docs/生产部署与运维手册.md` 支撑生产化叙事。
5. 投稿材料骨架已存在。`docs/trae-submission/process-log.md`、`community-post.md`、`assets-checklist.md` 已经覆盖过程证据、社区帖和资产清单。

## 最影响投资信任的缺口

### P0-1：缺少真实外部证据

当前 `docs/trae-submission/assets-checklist.md` 里体验链接、代码仓库链接、社区帖链接、演示视频链接、抖音视频链接都还未补齐。企业家不会只相信“项目很完整”，他们需要能点开、能看到、能转发、能复现。

验收标准：

- 一个公开可访问体验链接。
- 一个 15-30 秒短视频链接。
- 5 张核心截图：首页、建卡、AI 转译、分享页、7 日挑战。
- 至少 3 个关键 TRAE Session / 任务 ID 和对应截图。

### P0-2：缺少投资人听得懂的一句话商业定位

现在项目能力很多，但现场不能从“账号、支付、后台、小程序、合规”讲起。投资人优先听市场、用户、增长和收入路径。

建议统一为：

> 紫微星垣把高门槛紫微斗数转成可解释、可脱敏分享、可连续打卡的 AI 观察卡，用免费生成获客，用社交分享扩散，用私密报告和会员权益转化。

验收标准：

- 首页、社区帖、路演稿、README 开头都使用同一套定位词。
- 90 秒内说清“谁需要、为什么现在、怎么传播、怎么赚钱”。

### P0-3：缺少可被截图传播的视觉记忆点

首页和分享页已经有卡片雏形，但投资人会更容易被一张高完成度“星垣观察卡”打动，而不是被长文档和后台功能打动。

验收标准：

- 首页首屏、结果页和分享页出现同一套视觉资产和名称。
- 移动端 375px 宽度下，CTA 和结果卡一屏内可理解。
- 分享卡可作为短视频封面或朋友圈截图。

### P0-4：缺少增长/留存/转化的最小数据证明

项目已经有 7 日挑战、分享、报告和订单，但还缺少能让企业家判断商业价值的指标表达。

验收标准：

- 准备一个脱敏演示看板或静态指标区：生成数、分享点击、二次生成率、7 日挑战加入率、报告意向点击率。
- 明确标注“演示数据 / 内测数据 / 真实数据”，不要混淆。
- 路演中用 20 秒说明下一轮融资或资源要验证哪些指标。

### P0-5：真实商业化配置仍需明确边界

支付、短信、数据库、对象存储、观测都有 readiness 设计，但黑客松现场要坦诚：演示可用沙箱，正式上线需要微信支付/支付宝商户、短信网关、PostgreSQL、对象存储和监控配置。

验收标准：

- 路演中明确“沙箱闭环不等于真实收款”。
- `README.md` 或投稿材料中列出生产上线 blocker 和对应替换项。
- 现场演示以产品价值为主，不把真实支付配置当成核心卖点。

## 10 秒钩子

> 我把高门槛紫微斗数做成了一张 AI 观察卡：看得懂、能追溯、能脱敏分享，还能连续 7 天复访。

## 90 秒叙事

1. 用户问题：年轻用户对传统文化、自我探索和轻量情绪价值有需求，但传统命理术语难懂、表达容易绝对化，公开分享又有隐私风险。
2. 产品方案：紫微星垣用规则引擎和 AI 转译，把紫微斗数转成星垣观察卡，展示性格结构、关系模式和阶段节奏。
3. 差异化：比传统排盘更好懂，比泛 AI 占卜更可追溯，比真人咨询更低门槛、可标准化、可复看。
4. 增长闭环：免费观察卡获客，脱敏分享带来二次生成，7 日挑战提升复访，私密报告和会员权益形成收入。
5. 当前完成度：公开产品路径、报告、支付沙箱、订单、客服、隐私合规、生产化文档和自动化验证已经具备基础闭环。
6. 融资/资源诉求：需要资源验证真实移动端流量、微信/抖音传播、内容安全评测和付费转化。

## P2 优化清单

- 接入真实短信服务商和微信/支付宝沙箱到生产切换说明。
- 做 1-2 个真实用户访谈记录，验证“看得懂、愿意分享、愿意付费”的判断。
- 增加内容评测样例，证明 AI 表达能避免恐吓、绝对化和高风险建议。
- 准备小程序二维码或 WebView 承接录屏，作为移动端加分项。
- 做渠道合作页，面向达人、社群、传统文化内容号描述分发路径。

## 8 页投资人 deck 建议

1. 封面：紫微星垣，一张可解释、可分享、可持续观察的传统文化 AI 观察卡。
2. 用户痛点：传统术语难懂、泛 AI 不可信、分享有隐私风险、一次性报告留存弱。
3. 产品 Demo：从生成观察卡到脱敏分享和 7 日挑战。
4. 差异化：规则可追溯、AI 转译、隐私脱敏、连续观察。
5. 增长闭环：免费生成 -> 分享传播 -> 二次生成 -> 7 日挑战 -> 私密报告。
6. 商业模式：标准报告、高级报告、会员、主题追问、达人/社群合作。
7. 技术与合规：权限、脱敏、支付沙箱、生产数据库 readiness、测试验证。
8. 下一步诉求：流量、支付配置、内容安全评测、种子用户和投资沟通。

## 48 小时冲刺顺序

1. 先补所有投稿证据：体验链接、截图、录屏、Session ID。
2. 跑 `npm run verify:public`，保留终端截图。
3. 用固定演示数据录一版 3 分钟 Demo 和一版 30 秒短视频。
4. 首页/分享页再压一轮移动端视觉，确保“星垣观察卡”一眼可截图。
5. 写 8 页投资人 deck，赛后可以直接发给企业家。

## 子代理复盘

本轮采用子代理模式拆分为商业叙事、产品体验、技术可信度三条线。部分子代理因外部连接中断未完成，但主线程已根据当前代码、README、投稿材料和公开路径完成综合收敛。后续如果继续实施，建议继续按以下角色并行：

- 商业代理：只负责社区帖、deck、路演和投资人 Q&A。
- 产品代理：只负责首页、结果页、分享页、移动端截图和视频脚本。
- 技术代理：只负责 `verify:public`、部署 checklist、生产 blocker 和演示兜底。
