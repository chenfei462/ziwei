# 3 分钟路演脚本

## 目标

让评委和现场企业家在 3 分钟内记住三件事：

- 紫微星垣不是泛泛“算命网站”，而是传统文化 AI 观察卡。
- 它已经有可运行的公开产品闭环：建卡、解读、AI 转译、脱敏分享、7 日挑战、报告和支付沙箱。
- 它具备继续商业化的基础：低门槛内容、社交传播、隐私边界、生产化文档和自动化验证。

## 10 秒钩子

> 传统紫微斗数门槛很高，也容易被误解成绝对化预测。紫微星垣用 AI 把传统规则转译成一张可解释、可分享、可持续观察的“星垣观察卡”。

## 3 分钟脚本

### 0:00 - 0:20 痛点

传统命理知识很复杂，普通用户看不懂术语，也担心隐私泄露和绝对化判断。我们想做的是一个更安全、更现代的传统文化体验：不承诺“算准未来”，只帮助用户观察自己的性格结构、关系模式和阶段节奏。

### 0:20 - 0:45 方案

紫微星垣把传统紫微斗数规则转译成“星垣观察卡”。它的核心不是神秘结论，而是四件事：规则来源可追溯、现代语言可理解、公开分享可脱敏、日常挑战可复访。

### 0:45 - 1:25 现场生成

从首页点击“生成我的观察卡”，使用固定演示资料创建观察卡。展示结果页的三层信息：

- 十二宫结构化观察；
- 性格结构、关系模式、事业节奏等大众摘要；
- 今日星垣卡和 7 日观察挑战入口。

强调公开产品路径不会把阶段 Demo、后台入口或测试账号暴露给普通用户。

### 1:25 - 1:55 AI 转译

打开“AI 转译过程”，展示每段解读如何从传统术语和规则 trace 进入现代解释，并经过置信提示和安全过滤。说明模型不可用时会回退到本地规则模板，现场演示不会因为外部模型波动中断。

### 1:55 - 2:20 传播和留存

生成脱敏分享页，展示“已隐藏生日 / 已隐藏时间 / 已隐藏地点”等隐私 chips，再点击“我也生成一张”。然后展示 7 日观察挑战的可演示闭环：一次性建盘被设计成连续打卡、复访和社交传播理由；真实留存数据需要下一阶段用种子流量验证。

### 2:20 - 2:45 商业闭环

展示完整报告、标准/高级权益、订单、沙箱支付和客服入口。这里不要伪装真实支付已经上线，要明确这是可验证的商业化闭环：真实支付需要微信支付/支付宝商户配置后开启，当前演示用沙箱证明流程。

### 2:45 - 3:00 TRAE 过程证据

展示 `docs/trae-submission/process-log.md`、关键截图、Session ID 和验证命令结果，说明这个作品不是单页 Demo，而是通过 TRAE 从定位、产品路径、隐私边界、工程实现、测试验证到投稿材料逐步迭代出来的产品雏形。

## 90 秒投资人版本

> 紫微星垣面向的是中国移动端用户对传统文化、自我观察和轻量情绪价值的需求。我们不做高风险的“命运断言”，而是把紫微斗数规则转译成可解释、可脱敏分享、可连续打卡的 AI 观察卡。
>
> 当前项目已经跑通公开产品闭环：匿名建卡、结构化解读、AI 转译、脱敏分享、今日卡、7 日挑战、报告权益、沙箱支付、订单、客服和合规页面。对投资人来说，它的价值不在于一个玄学工具，而在于把高门槛传统知识产品化成低门槛内容消费、社交传播和私密报告付费路径。
>
> 下一步需要补的不是更多散功能，而是三件事：真实部署和演示资产、增长/留存数据证明、以及微信支付/支付宝/短信等中国商业化配置。补齐后，它可以从黑客松作品进入小规模冷启动验证。

## 备用路线

- 网络慢：播放本地录屏，同时展示首页、结果页、AI 转译、分享页和验证命令截图。
- 模型不可用：展示本地规则 fallback 和 AI 生成说明，不现场依赖外部模型。
- 支付链路不稳定：明确使用沙箱支付录屏，不把沙箱伪装成真实资金支付。
- 分享页异常：展示已生成的脱敏分享页截图和 Open Graph 预览图。

## 现场答辩锚点

- 创新性：传统术语 -> 规则 trace -> AI 转译 -> 安全过滤 -> 可分享观察卡。
- 实用性：普通用户不需要懂紫微术语，也能获得自我观察和日常复访路径。
- 完成度：公开路径、报告、支付沙箱、订单、客服、隐私、测试和生产化文档均已形成基础闭环。
- 设计体验：首页、结果页、分享页围绕同一张“星垣观察卡”收敛，不让评委迷失在工程细节里。
- 商业化：免费观察卡获客，脱敏分享传播，7 日挑战留存，私密报告和会员权益转化。
