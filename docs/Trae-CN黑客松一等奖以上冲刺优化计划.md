# Trae CN 黑客松一等奖以上冲刺优化计划

## 目标判断

紫微星垣现在已经不是单点 Demo：仓库中已有公开首页、建盘、命盘解读、报告、支付沙箱、脱敏分享、微信分享、小程序承接、后台治理、生产数据库和部署运维文档。要冲 TRAE AI 创造力大赛一等奖以上，下一阶段不应该继续平均加功能，而要把项目包装成一个评委能在 3 分钟内记住、能相信完整度、能看到 TRAE 创作过程、能被现场路演放大的作品。

推荐参赛定位：

> 紫微星垣：用 AI 把传统命理知识转译成可验证、可脱敏分享、可持续观察的数字文化体验。

推荐赛道：

- 主赛道：生活娱乐 / 造点新花样
- 可叠加叙事：古籍活化工具、非遗创新创意开发
- 不建议主打：纯商业付费报告。它会削弱公益文化、AI 创造力和黑客松作品气质。

## 官方约束倒推

来自官方页面和社区规则的关键要求：

- 初赛：用 TRAE 把创意做成能运行、能体验的 Demo。
- 复赛：在初赛 Demo 基础上完善为具备完整用户路径和核心能力的正式产品。
- 决赛：线下路演，完成作品展示、项目讲解和现场答辩。
- 作品需使用 TRAE Work 或 TRAE IDE 创作，并提供 AI 对话截图、任务历史、关键 Session ID、阶段成果截图等过程证明。
- 作品原则上应有可运行体验链接或 HTML 文件；社区发帖只支持文字、图片、GIF、链接和 20M 以内文件，大体积视频/代码库应外链。
- 抖音人气通道独立存在，重点看可传播短视频素材。

参考链接：

- TRAE AI 创造力大赛官网：https://www.trae.cn/ai-creativity
- TRAE 官方中文社区规则总览：https://forum.trae.cn/t/topic/22547

## 当前冲奖差距

### 1. 缺少一个一眼记住的现场爆点

现在主流程能跑，但最强记忆点仍然偏“生成一份命盘/报告”。一等奖以上需要一个可以被截图、录屏、短视频传播的瞬间。

应新增：

- 一张高完成度的“星垣观察卡”视觉结果：可保存、可分享、可作为视频封面。
- 一个 7 日观察挑战的真实进度条和打卡反馈，而不是说明性文案。
- 一个 AI 解释层：展示“为什么这么解读”，把规则 trace、传统术语、现代解释和置信度串起来。

验收标准：

- 首页、命盘页、分享页都能看到同一套视觉资产和概念名称。
- 评委不需要看 README，也能在首屏知道它是“传统文化 AI 观察卡”。
- 3 分钟演示中有一个明确的“哇，这个可以发朋友圈/抖音”的画面。

### 2. TRAE 创作证据链缺失

比赛不是只评代码，还评用 TRAE 把想法变成作品的过程。当前已经建立 `docs/trae-submission/` 参赛材料骨架，但还需要补齐真实 Session ID、截图、录屏链接和阶段演进说明。

应新增：

- `docs/trae-submission/`：集中保存创作证据。
- `docs/trae-submission/process-log.md`：按日期记录 TRAE 任务、目标、关键决策和 Session ID。
- `docs/trae-submission/community-post.md`：初赛/复赛社区帖子草稿。
- `docs/trae-submission/demo-script.md`：3 分钟路演脚本。
- `docs/trae-submission/assets-checklist.md`：截图、GIF、视频、体验链接、二维码、代码仓库链接清单。

验收标准：

- 每个核心功能都能对应一个 TRAE 过程证据。
- 社区帖子可以直接发布，不需要临场重写。
- 决赛答辩能回答“哪些工作由 TRAE 完成、如何协作、遇到问题如何迭代”。

### 3. 文化价值叙事还不够强

“紫微斗数产品”容易被理解成泛娱乐算命；“传统知识的可解释化、脱敏化、日常观察化”才是更适合比赛的表达。

应重写叙事：

- 不说“算命更准”，说“把复杂传统术语转译成可自我观察的结构化卡片”。
- 不说“付费报告”，说“从公开观察卡到私密深度报告的文化体验路径”。
- 不说“AI 玄学”，说“AI 辅助传统规则解释、内容安全过滤和现代语言转译”。

验收标准：

- 首页、README、社区帖、演示稿统一使用同一套定位词。
- 明确免责声明：娱乐、自我观察、传统文化体验，不做医疗、投资、法律、婚恋成败或灾祸预测。
- 规则来源、置信度和隐私边界成为产品亮点，而不是角落说明。

### 4. AI 能力展示不够显性

仓库里已有 AI follow-up、prompt 版本、生成记录、安全过滤和 fallback，但公开演示很容易只看到普通规则应用。

应把 AI 显性化：

- 命盘结果页加入“AI 转译过程”折叠区：传统术语 -> 规则来源 -> 现代解释 -> 安全改写。
- 增加 3 个固定追问按钮：今天适合观察什么、关系互动要注意什么、本周节奏如何安排。
- 在报告页展示 prompt 版本、模型状态、fallback 状态和内容安全状态的脱敏摘要。

验收标准：

- 评委能清楚看到 AI 参与了表达、总结、追问和安全过滤。
- 即使模型不可用，也能展示 fallback，不会现场翻车。
- AI 过程展示不泄露完整出生资料和 prompt 机密。

### 5. 移动端短视频传播素材不足

官方有抖音人气通道，项目必须能被 15-30 秒讲清楚。当前更像网页产品，不够短视频化。

应新增：

- 手机竖屏优先的分享卡和结果页布局。
- 15 秒视频脚本：输入生日 -> 生成观察卡 -> 隐私脱敏 -> 7 日挑战。
- 30 秒视频脚本：传统术语太难懂 -> AI 转译 -> 今日卡 -> 分享给朋友。
- 抖音标题和标签包：`#vibecoding大赏 #traeai创造力大赛 #传统文化AI #紫微星垣`。

验收标准：

- 手机端首屏不拥挤，CTA 和结果卡在一屏内完成理解。
- 生成的分享图适合做视频封面。
- 有可复制的抖音发布文案和封面文案。

### 6. 复赛完整产品感还要压实

项目已有很多生产化能力，但对外演示要避免给人“工程很大但主线散”的感觉。

复赛要强化一条闭环：

```text
首页理解价值
创建观察卡
查看结构化解读
生成今日星垣卡
脱敏分享
对方二次生成
7 日挑战留存
解锁私密深度报告
```

验收标准：

- E2E 覆盖完整公开路径，并有移动端项目。
- 公开路径不出现 phase、demo、测试账号、后台入口。
- 支付/报告如只做沙箱，演示中必须明确是“沙箱闭环”，不要伪装真实支付。

## 一等奖以上优先级

### P0：必须做，否则很难冲大奖

1. 建立参赛材料目录和证据链  
   交付：`docs/trae-submission/process-log.md`、社区帖、路演脚本、资产清单。

2. 做一个强视觉“星垣观察卡”  
   交付：首页/结果页/分享页统一视觉卡；可截图、可视频封面化。

3. 把“AI 转译传统规则”的过程显性化  
   交付：规则来源、传统术语、现代解释、置信度、安全过滤四段式展示。

4. 让 7 日挑战变成真实可交互功能  
   交付：加入挑战、今日打卡、连续天数、成就提示、分享激励。

5. 准备 3 分钟现场 Demo  
   交付：脚本、固定测试数据、备用录屏、离线截图、失败兜底路线。

6. 建立公开路径一键验收命令  
   交付：`npm run verify:public`，串联 typecheck、公开主流程单测、build 和 public e2e，降低评审复现摩擦。

### P1：强烈建议，决定能否从入围到前排

6. 移动端和微信/抖音分享体验  
   交付：移动端截图、分享图、二维码、短视频脚本。

7. 作品叙事统一化  
   交付：README 开头、首页文案、社区帖、路演稿统一为“传统文化 AI 观察卡”。

8. 演示数据与样例库  
   交付：3 个匿名样例：学生/职场/亲密关系边界，展示不同结果但不泄露隐私。

9. 性能与稳定性兜底  
   交付：一键启动说明、健康检查、公开路径 e2e、模型不可用 fallback 演示。

10. 评审问答库  
    交付：10 个答辩问题：创新性、合规、文化价值、AI 参与度、商业化、隐私、准确性边界、用户留存、TRAE 协作、扩展计划。

### P2：有时间再做，帮助冲全场奖

11. 古籍/传统术语知识图谱小模块  
    把“命宫、福德、四化”等术语做成可点击解释，与古籍活化叙事挂钩。

12. 可导出的长图/PDF  
    比报告页更适合传播和评审留存。

13. 运营看板演示模式  
    展示分享率、打卡率、二次生成率，但必须使用假数据或脱敏聚合。

14. 小程序二维码承接  
    作为移动体验加分项，不作为主 Demo 依赖。

## 7 天冲刺路线

### Day 1：定叙事和材料骨架

- 写完社区帖草稿。
- 写完 3 分钟演示脚本。
- 建立 TRAE 过程证据清单。
- 固定参赛定位和赛道。

### Day 2-3：做爆点视觉和主流程

- 设计星垣观察卡。
- 接到首页、命盘页、分享页。
- 补移动端样式。
- 录第一版 30 秒视频。

### Day 4：AI 过程显性化

- 加 AI 转译过程展示。
- 加固定追问入口。
- 确保模型失败 fallback 可演示。

### Day 5：7 日挑战闭环

- 加入挑战、打卡、连续天数、成就提示。
- 分享页强化“我也生成一张”和“加入 7 日观察”。

### Day 6：硬化演示和验证

- 跑 `npm run typecheck`、`npm test`、`npm run build`、核心 e2e。
- 准备备用录屏和截图。
- 写答辩 Q&A。

### Day 7：投稿包和传播包

- 社区帖定稿。
- 抖音视频和封面定稿。
- 整理体验链接、代码链接、截图、GIF、Session ID。
- 做一次完整路演彩排。

## 3 分钟路演脚本

```text
0:00 - 0:20
痛点：传统命理知识门槛高，普通人看不懂，也担心隐私泄露和绝对化判断。

0:20 - 0:45
方案：紫微星垣把传统规则转译成一张“AI 观察卡”，只做娱乐、自我观察和传统文化体验。

0:45 - 1:30
现场生成：输入必要资料 -> 生成观察卡 -> 展示性格结构、关系模式、阶段节奏。

1:30 - 2:05
AI 解释：展示规则来源、传统术语、现代解释、置信度和安全过滤。

2:05 - 2:30
传播与留存：生成今日星垣卡 -> 脱敏分享 -> 朋友二次生成 -> 7 日挑战。

2:30 - 2:50
完整产品：报告、权益、隐私、生产化、移动分享都已形成闭环。

2:50 - 3:00
TRAE 证据：展示从创意、原型、实现、测试到路演材料的 TRAE 协作过程。
```

## 最推荐的下一步
