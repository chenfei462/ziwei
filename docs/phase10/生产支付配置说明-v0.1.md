# 生产支付配置说明 v0.1
## 中国市场支付 Provider

当前代码提供四类 provider：

- `wechat_pay_reserved`：中国市场默认 provider。生产启用需要 `WECHAT_PAY_MCH_ID`、`WECHAT_PAY_APP_ID`、`WECHAT_PAY_API_V3_KEY`、`WECHAT_PAY_MERCHANT_SERIAL_NO`、`WECHAT_PAY_PRIVATE_KEY`、`WECHAT_PAY_PLATFORM_CERTIFICATE`、`WECHAT_PAY_CHECKOUT_BASE_URL` 和 `CHINA_PAYMENT_PRODUCTION_ENABLED=true`。
- `alipay_reserved`：支付宝 provider。生产启用需要 `ALIPAY_APP_ID`、`ALIPAY_PRIVATE_KEY`、`ALIPAY_PUBLIC_KEY`、`ALIPAY_CHECKOUT_BASE_URL` 和 `CHINA_PAYMENT_PRODUCTION_ENABLED=true`。
- `stripe_checkout`：保留给海外或历史链路。
- `mock_checkout`：仅用于自动化测试和预发演练。

微信支付和支付宝在缺少商户密钥、证书、支付主体或回调域名时只进入 sandbox readiness，不会假装生产可用。checkout session 会暴露 `provider_requirements`，包括验签密钥环境变量、签名 header 和幂等键来源。

## Webhook 和幂等

- 公开回调入口为 `POST /api/payment/webhook?provider=stripe_checkout|wechat_pay_reserved|alipay_reserved|mock_checkout`，服务端按 provider 选择签名 header，不信任浏览器 Origin。
- 微信支付 webhook 使用 `wechatpay-signature` 作为签名 header，代码使用 `WECHAT_PAY_API_V3_KEY` 完成 sandbox/生产验签抽象。
- 支付宝 webhook 使用 `alipay-signature` 作为签名 header，代码使用 `ALIPAY_PUBLIC_KEY` 完成 sandbox/生产验签抽象。
- Stripe webhook 使用 `stripe-signature`，mock provider 使用 `mock-signature`。
- provider webhook 的幂等键统一使用 `provider_event_id`，重复回调不会重复发放权益。
- 生产接入真实 SDK 或 HTTP 网关时，必须保持当前 `PaymentWebhookRequest` 的验签、状态机和幂等语义不变。

## 范围

阶段 10 将阶段 9 的 `stripe_checkout` 沙箱闭环扩展为可灰度的生产开关。生产支付必须同时满足 live key、webhook secret、生产开关、灰度比例和回滚关闭。

## 环境变量

- `STRIPE_SECRET_KEY`：生产模式必须以 `sk_live_` 开头。
- `STRIPE_WEBHOOK_SECRET`：生产 webhook 签名校验必需。
- `PHASE10_PRODUCTION_PAYMENT_ENABLED`：值为 `true` 时才允许生产支付。
- `PHASE10_PAYMENT_ROLLOUT_PERCENT`：0-100 的灰度比例。
- `PHASE10_PAYMENT_ROLLBACK`：值为 `true` 时强制回到沙箱模式。
- `PHASE10_ADMIN_TOKEN`：运营后台 API 访问令牌。

## 运营退款、补发和对账

- 全额退款使用 `markManualRefund`/`/api/ops/order/{id}/refund`，订单进入 `refunded`，对应报告权益被撤回。
- 部分退款通过同一路径传入 `amount_cents`，订单进入 `partially_refunded`，保留已购报告访问权，退款原因会脱敏后写入订单和 ops note。
- 客服补发权益使用 `/api/ops/order/{id}/entitlement/reissue`，仅 `ops_admin` 或 `support_agent` 可执行，操作写入 `entitlement_reissued` 审计 note。
- 对账摘要使用 `/api/ops/reconciliation`，按 provider 汇总订单数、支付事件数、总额、退款额、净额、重复 webhook、权益缺口和 provider statement 摘要。`POST /api/ops/reconciliation/preview` 仅允许 `ops_admin` 在正式导入前预检微信/支付宝账单，返回匹配行、金额不一致、孤儿流水和脱敏 Payment Alerts，`persistence.persisted=false`，不写入 `provider_statements`，不写入导入审计，raw reference 只生成 digest。正式导入仍使用 `POST /api/ops/reconciliation/import`，导入后写入 `ops_provider_statement_imported` 审计。`alerts` 字段会把金额不一致、孤儿流水、重复 webhook 和权益缺口汇总为脱敏 Payment Alerts，内部商业后台会展示严重级别、计数、provider 和处置建议；告警不包含原始账单备注、第三方身份明文、联系方式、出生资料或报告正文。`ops_admin` 可调用 `POST /api/ops/reconciliation/alerts` 生成并投递外部告警 webhook envelope，payload 只包含脱敏告警摘要、幂等 key、endpoint digest 和 HMAC-SHA256 签名；投递响应只保留 HTTP status 与 response digest。缺少 `OBS_ALERT_WEBHOOK_URL` 或 `OBS_ALERT_WEBHOOK_SECRET` 时返回 blocked/dry-run，投递失败返回 failed，并写入 `ops_payment_alert_webhook_prepared` 审计，不泄露 webhook URL、secret 或响应正文。内部商业后台已提供 `ops_admin` dry-run/send 操作，浏览器请求体只携带 mode 与脱敏 reason；`support_agent` 为只读。正式上线后仍需导入微信/支付宝平台账单和银行流水做人工复核，并完成外部告警 webhook 演练。

## 默认策略

默认生产支付关闭，灰度比例为 0。人工退款和部分退款只标记订单与权益，不调用微信/支付宝真实退款网关；真实退款网关必须在商户资质、证书、回调和财务审批流程补齐后启用。
