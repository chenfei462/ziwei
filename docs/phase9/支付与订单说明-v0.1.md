# 支付与订单说明 v0.1

## 范围

阶段 9 将阶段 8 的报告草稿推进到最小商业闭环：创建订单、创建 `stripe_checkout` 会话、处理签名 webhook、授予报告权益。

## 订单状态

- `created`：订单已创建，尚未进入支付。
- `pending_payment`：已创建 checkout session。
- `paid`：支付事件确认成功的中间状态。
- `fulfilled`：报告权益已授予。
- `failed`：支付失败或 checkout 过期。
- `cancelled`：用户取消 checkout。
- `refunded` / `partially_refunded`：客服或支付 provider 标记退款。

全额退款会撤回报告权益；部分退款保留报告访问权并记录 `refunded_amount_cents` 与脱敏 `refund_reason`。客服补发权益必须走后台接口并写入审计 note。

## 接口

- `POST /api/order/create`
- `GET /api/order/{id}`
- `GET /api/order/list`
- `POST /api/checkout/session`
- `POST /api/payment/webhook?provider=stripe_checkout|wechat_pay_reserved|alipay_reserved|mock_checkout`
- `GET /api/entitlement/report/{report_id}`
- `GET /api/member/me`
- `GET /api/ops/commercial/dashboard`（管理员凭据）
- `GET /api/ops/reconciliation`
- `POST /api/ops/order/{id}/entitlement/reissue`

## 隐私

订单、支付事件、权益和看板只保存 `report_id`、`member_id`、金额、状态和脱敏报告快照，不保存完整出生日期、出生时间、地点详情、摄像头帧或背景图像。

## 中国市场 Provider 边界

微信支付回调必须携带 `wechatpay-signature`，支付宝回调必须携带 `alipay-signature`。当前 provider adapter 已完成签名、幂等、订单状态和权益发放语义；真实商户号、证书、API v3 key、支付宝公钥/私钥、回调域名、退款 API 和平台账单导入仍需运营方完成外部资质和密钥配置后启用。
